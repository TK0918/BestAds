# 运营端组件规范

> 版本：`v1.0.0`
> 日期：`2026-08-09`
> 范围：`admin-system/` HTML 原型、`prototype-kit/admin-shell/` 公共组件。

## 1. 规范来源

- 视觉基线：OPS 2.0 Figma，只读使用。
- 实现基线：真实运营端 Vben Admin + Ant Design Vue + VXE Grid。
- 原型实现：`prototype-kit/admin-shell/figma-ops.css`、`admin-page.css`、`admin-page.js`、`admin-module-page.js`、`admin-business-page.js`。

## 2. 页面布局

- 页面内容区不额外展示大标题和说明文案；页面定位由 Header 面包屑、页面 Tab、列表卡片标题承担。
- 列表页标准结构为：查询卡片、列表卡片、表格、分页。
- 查询卡片、统计维度卡片、图表卡片和列表卡片之间保持统一 `16px` 间距。
- 主要列表页最小宽度不低于 `1180px`，横向内容通过表格滚动承载。
- 绩效、Meta资产管理、FB业务管理、TT业务管理、GG业务管理、其他媒体业务等模块页优先使用 `admin-module-page.js` 配置驱动，不在 HTML 中重复写完整表格样式和菜单。
- 业务管理模块的字段、按钮、列表样例和弹窗配置集中维护在 `prototype-kit/admin-shell/admin-business-page.js`。
- 广告管理、客户流水、监控管理、报表、系统配置等历史页面不得依赖全局样式桥接层粗暴覆盖；应按模块逐页迁移为标准 `admin-card / filter-grid / admin-table / btn` 结构或配置驱动页面，并逐页确认筛选项、列表字段、按钮、弹窗和交互。

## 3. 表单控件

- 输入框、选择器、日期控件高度统一为 `32px`。
- 字段标签在控件上方，标签与控件间距为 `6px`。
- 查询区默认四列布局；字段较多时保持四列并换行，不压缩控件宽度。
- placeholder 规则：文本输入使用 `请输入 + 字段名`，选择器使用 `请选择 + 字段名`。
- 时间范围筛选使用公共 `daterange` 控件，单个筛选项内展示开始日期、`至`、结束日期；筛选逻辑按行数据日期前 10 位做闭区间匹配。
- 自然周等非标准日期范围使用公共 `textrange` 控件，视觉仍为开始输入、`至`、结束输入；不得强行改成日期控件。
- 批量 ID 类筛选可使用输入框或 textarea 承载多值内容；出现在查询区时控件高度仍保持 `32px`，不因 textarea 类型撑高整行布局。
- 查询区多选筛选项使用下拉触发器 + checkbox 选项面板，不使用浏览器原生 `select[multiple]`；多选条件按「任一选中值命中」过滤。
- PRD 中用于解释字段规则的说明文案不得直接放在查询区控件下方占高度；能通过 placeholder、交互或验收规则实现的，不在页面额外展示说明。

## 4. 按钮

- 主按钮用于新增、查询、确定等主要动作。
- 普通按钮用于重置、取消、自定义字段等次要动作。
- 禁用按钮用于未选择数据、无权限、提交中等状态。
- 批量操作未选择数据时必须禁用，点击时仍需校验选中状态。
- 查询区 `搜索 / 重置` 按钮固定放在查询卡片内右下角，不能因筛选项数量、textarea 或多选控件导致按钮漂移到中间列或挤出查询区。
- 按钮组使用固定 `gap`，不通过空格、换行或 margin 堆叠控制间距。
- 列表工具栏按业务影响分组：会影响业务数据的操作放左侧；自定义字段、下载导入模版、导出数据等不影响业务数据的工具类操作默认放右侧。
- 上传类按钮如测试环境为本地文件选择器，则原型点击后也应触发 `input[type=file]` 文件选择，不使用普通表单弹窗替代。

## 5. 表格

- 选择列固定左侧，宽度 `50px`。
- 测试环境存在批量操作的列表必须显示选择列；例如业务管理的账户管理页、账户分配页，列表首列为复选框。
- 操作列固定右侧，默认宽度 `280px`。
- 金额、额度、比例、数量字段右对齐，并优先支持排序。
- 状态字段使用 Tag；空值统一显示 `-`。
- 横向字段较多时保留横向滚动，不压缩到不可读。

## 6. 操作列

- 行内操作使用文字链接，不使用实心按钮。
- 单个操作文案必须保持在同一行；例如 `子账号管理`、`重置密码` 不得拆成两行。
- 操作按钮组可按按钮为单位换行，使用 `flex-wrap: wrap` 和固定 `gap`。
- 危险操作使用危险色文本或危险确认弹窗，例如重置密码、禁用、回退、清零。

## 7. 弹窗

- 普通编辑弹窗使用两列表单网格。
- 确认弹窗用于重置密码、禁用、回退、资金类操作等高风险动作。
- 弹窗底部操作区右对齐，按钮顺序为取消、确定。
- 弹窗字段必须来自页面契约，不得复用其他页面的临时字段。

## 8. 排序

- 可排序表头显示升序、降序图标。
- 点击顺序为：升序、降序、恢复默认。
- 客户管理已确认排序字段：客户ID、商户ID、当前余额、已用额度、信用额度、预充金额上限、剩余预充金额、可用余额、真实金额、冻结金额。
- 其他页面的排序字段按页面契约确认后再固化。

## 9. 业务管理模块页面规则

- 账户管理页面标准筛选：广告账户ID、广告账户名称、状态、币种、开户代理、账户类型；其他媒体业务额外包含媒体字段，且测试环境当前不展示状态/时区/总消耗/消耗上限/创建天数。
- 账户管理页面列表首列必须有复选框；`修改代理`、`修改账户类型` 初始禁用，勾选至少一个广告账户后启用。
- `修改代理` 弹窗标题为 `修改开户代理`，字段只有 `开户代理`；`修改账户类型` 弹窗标题为 `修改账户类型`，字段只有 `账户类型`。
- 账户管理页工具栏左侧为上传广告账号、修改代理、修改账户类型；右侧为自定义字段、下载导入模版、导出数据。
- 开户管理、账户分配、账户充值/减款/清零、服务费等业务列表同样遵循工具栏左右分组：业务写操作放左侧；自定义字段、下载模版、导出数据等工具类操作放右侧。
- `自定义字段` 打开字段显示/隐藏抽屉，包含当前列表字段、恢复默认、取消、确定。
- 自定义字段抽屉必须与列表字段联动：取消勾选后对应表头和单元格立即隐藏，重新勾选后恢复显示。
- 自定义字段抽屉必须支持拖拽排序：拖拽字段后列表表头和单元格按新顺序立即重排。
- 自定义字段至少保留一个可见字段；恢复默认需要还原全部字段和默认顺序。
- 账户分配页面必须包含 `当前分配 / 分配日志` Tab；当前分配页顶部按钮为批量解除、分配账户、自定义字段、导出数据。筛选区必须包含 `BD`、`AM`、`广告账户状态`；当前分配列表必须包含 `BD`、`AM`、`广告账户状态`、`广告账户币种`、`广告账户余额`，且导出字段需要与列表口径一致。`批量解除` 未勾选账户时禁用，勾选后启用；点击后展示确认弹窗：`确定将选择的账户批量解除绑定吗?（账户个数:N）`，提示 `将解除所有选中的客户和广告账户关系`。
- `批量解除` 确认后，当前页选中绑定关系必须从列表中消失；刷新页面后恢复默认 fixture 数据。
- `分配账户` 弹窗以测试环境为准：包含 `客户（单选）` 和 `广告账户（多选）`；广告账户表格字段为 `账户 / 状态 / 不可用原因`，不可用账户禁用勾选；确认后当前页新增分配记录。
- 账户充值、账户减款、账户清零页面使用同一类资金工单布局：提交时间、工单ID、广告账户、是否绑卡户、商户ID内容、客户信息、一代、状态；其他媒体业务额外包含媒体字段。
- `发起充值` 弹窗以测试环境为准：先通过 `客户（单选）` 搜索/选择客户，客户选项展示客户名称、客户ID和商户ID；选中客户后加载该客户下广告账户表格，广告账户支持多选；选中广告账户后展示逐账户 `充值金额设置`。
- `充值金额设置` 单行展示规则：左侧展示账户名称、当前余额、服务费、预收税费、实际到账；右侧固定展示充值金额输入框。输入金额后必须即时计算并展示服务费、预收税费、实际到账和总充值金额。
- `发起减款` 弹窗以测试环境为准：包含 `客户（单选）` 和 `广告账户（多选）`；广告账户表格字段为 `账户名称 / 账户币种 / 可减款金额`；选中账户后展示 `减款金额设置`。点击确定后必须先弹事前确认：建议账户停止投放 48 小时后再来减款、最终减款金额以结算时金额为准、本次将提交 N 个账户的减款申请；确认后当前页新增待处理减款工单。减款不做近 2 天消耗硬校验。
- `发起清零` 弹窗以测试环境为准：包含 `客户（单选）` 和 `广告账户（多选）`；广告账户表格字段为 `账户名称 / 账户币种 / 可清零金额 / 近 2 天消耗 / 不可清零原因`；近 2 天（昨天+当天）有消耗的账户复选框禁用，不可勾选，不可提交；无消耗或查不到消耗允许勾选。选中账户后展示 `清零金额设置`，清零金额默认等于可清零金额且只读；点击确定后必须先弹事前确认：建议账户停止投放 48 小时后再来清零、最终清零金额以结算时金额为准、近 2 天有消耗不可清零、本次将提交 N 个账户的清零申请；确认后当前页新增待处理清零工单。
- 其他媒体业务只有清零，没有减款；原因是无法获取广告账户余额，无法确定可减款金额。其他媒体清零的余额/可清零金额可展示为 `-` 或待媒体结算，但仍允许发起清零。
- 清零/减款 `处理成功`、`媒体已完成` 必须进入事中金额确认：运营填写本次实际加回客户钱包金额；传统户清零基准为清零提交时账户余额，绑卡户清零基准为处理当下使用卡剩余额度，减款基准为申请减款金额。若基准缺失或为 0，弹 `无法校验金额偏差`；若 `|本次输入金额 - 基准金额| / |基准金额| >= 5%`，弹 `金额偏差较大，请二次确认`。两种确认都不硬拦，支持返回修改或已知悉确认提交；偏差小于 5% 时直接完成处理。
- 清零页 `处理失败` 默认禁用；只有选中可处理的待处理清零工单后才启用。确认处理失败后，选中工单状态更新为 `失败`，并禁用再次选择。
- 账户余额日环比异常页归属 `监控管理`，菜单文案为 `账户余额日环比`。页面用于清零/减款风控事后闭环，筛选字段必须覆盖核对日期、媒体、是否绑卡户、跟进状态、广告账户ID、商户ID、客户名称、BD、AM；列表必须覆盖核对日期、商户ID、客户名称、BD、AM、广告账户、媒体、是否绑卡户、币种、前一天日终余额、当天充值、当天消耗、当天清零、当天减款、推算余额、当天日终余额、差额、偏差%、跟进信息和操作。金额/比例列支持排序。
- Meta资产管理 `资产` Tab 的广告账户列表，筛选区和列表都必须包含 `BD`、`AM` 字段。
- 服务费页面顶部按钮为新增配置、批量修改状态、批量修改服务费、导出数据；GG 和其他媒体业务菜单文案为 `账户服务费`，FB 和 TT 当前为 `服务费配置`。
- 资金类动作按钮在原型中只展示弹窗或 Toast，不调用测试环境接口，不模拟真实提交。

## 10. 客户流水模块页面规则

- 客户流水模块使用 `prototype-kit/admin-shell/admin-customer-transactions-page.js` 集中维护页面契约，不在 HTML 中手写菜单、筛选区、表格和弹窗。
- 客户流水当前包含 3 个页面：`交易明细`、`在线充值`、`线下转账`。页面 HTML 只保留公共 Shell 壳、`data-admin-page` 和脚本引用。
- 三个页面筛选区必须优先包含客户身份字段：时间、客户ID、商户ID、客户名称、客户邮箱；商户ID按公司客户身份 ID 口径展示。
- `交易明细` 列表必须覆盖流水号、客户ID、商户ID、客户名称、客户邮箱、交易时间、变动原因、交易类型编码、钱包币种、变动金额、变动前余额、变动后余额、关联业务单号、备注。金额和余额字段右对齐并支持排序。
- `在线充值` 列表必须覆盖充值单号、客户ID、商户ID、客户名称、客户邮箱、充值时间、支付平台、平台支付ID、支付币种、支付金额、充值状态、入账币种、入账金额、完成时间、备注。
- `线下转账` 列表必须覆盖转账单号、客户ID、商户ID、客户名称、客户邮箱、提交时间、支付平台、平台支付ID、支付币种、支付金额、凭证、审核状态、入账币种、入账金额、审核时间、审核人、备注。
- `线下转账` 待审核数据行操作为 `审核`、`查看凭证`；已成功/失败数据行操作为 `查看详情`、`查看凭证`。
- `线下转账审核` 弹窗必须展示转账单号、客户、支付平台、支付金额，并要求填写入账币种、入账金额、审核结果、备注。确认后只更新原型当前行状态，不提交测试环境。
- `查看凭证` 弹窗只展示脱敏 Fixture 的平台、平台支付ID、支付金额和凭证文件占位，不加载真实附件。

## 11. 监控管理模块页面规则

- 原 `余额监控管理` 一级菜单更名为 `监控管理`；该分组承载所有监控类页面，不只包含余额监控。
- 监控管理模块使用 `prototype-kit/admin-shell/admin-monitor-page.js` 集中维护页面契约，不在 HTML 中手写菜单、筛选区、表格和弹窗。
- 监控管理当前包含 3 个二级页面：`余额监控&自动充值`、`账户封停监控`、`账户余额日环比`。
- `余额监控&自动充值` 对齐测试环境 `/balance-monitor-auto-recharge`，本地继续使用 `admin-system/auto-recharge/notifications.html` 承载，避免破坏旧链接。
- `余额监控&自动充值` 必须包含 5 个 Tab：`余额监控设置`、`余额监控日志`、`自动充值设置`、`自动充值日志`、`自动充值变更日志`。
- `余额监控设置` 筛选字段为规则名称；列表字段为规则名称、条件、状态、最短通知间隔、账户数、最后更新人、更新时间、操作；主按钮为 `新增监控规则`，行操作为 `编辑`。
- `余额监控日志` 筛选字段为判断时间、是否有发送飞书通知、未发送原因；列表字段为判断时间(+8)、规则名称、媒体平台、代理、广告账户ID、广告账户名称、命中时余额、规则阈值、通知人、是否有发送飞书通知、未发送原因。
- `自动充值设置` 筛选字段为商户 ID、客户名称、规则名称、状态、广告账户 ID；列表字段为商户 ID、客户名称、规则名称、条件、充值金额、冷却期、单日上限、状态、生效时间、账户数、创建人、最后修改人、修改时间、操作；主按钮为 `代客新增规则`，行操作为 `编辑`。
- `自动充值日志` 筛选字段为判断时间、商户 ID、客户名称、媒体平台、代理、广告账户 ID、广告账户名称、执行结果、跳过原因；列表字段为判断时间(+8)、商户 ID、客户名称、规则名称、媒体平台、代理、广告账户ID、广告账户名称、命中时余额、规则阈值、充值金额、自动充值冷却期、单日充值次数上限、当日已自动充值发起成功次数、执行结果、跳过原因、充值单ID。
- `自动充值变更日志` 筛选字段为操作时间、操作人、商户 ID、客户名称、规则名称、操作类型；列表字段为操作时间、操作人、商户 ID、客户名称、规则 ID、规则名称、操作类型、变更摘要、操作来源、备注。
- `客户端规则` 不再作为独立页面维护；原 `admin-system/auto-recharge/client-rules.html` 删除，相关规则以 `自动充值设置` Tab 表达。
- `账户封停监控` 包含 `监控记录 / 封停统计` Tab。监控记录筛选必须覆盖监控日期、监控批次、事件类型、媒体平台、广告账户ID、商户ID、客户名称、BD、AM、跟进状态；列表必须覆盖监控时间、批次、事件类型、媒体、广告账户、商户与客户、BD/AM、账户币种、余额、账户状态、跟进信息。

## 13. 主题

- 所有接入公共 Shell 的页面必须支持浅色/深色切换。
- 主题切换影响范围包括侧边栏、Header、Tab、卡片、表单、表格、固定操作列、弹窗、分页和 Toast。
- 主题状态保存在 `bestads-theme`。

## 14. 历史页面过渡规范

- 历史页面不得继续维护自定义侧边栏视觉；侧边栏、Logo、Header、Tab、主题切换必须由 `admin-shell.js` 接管。
- 历史页面允许在短期内保留已有业务 DOM，但进入规范化范围后必须迁移为公共组件结构或配置驱动页面，不再新增 Tailwind 手写页面。
- 逐模块迁移时，优先处理用户正在验收的页面；同模块内字段、按钮、弹窗和交互必须放在同一配置文件中维护，避免页面之间规则漂移。
- 模块迁移完成后，需要同步补充本规范中的模块专用规则，沉淀为后续原型生成约束。
