## 3. 已确认的页面契约草案

### 3.1 页面公共 Shell

- 左侧运营端菜单、顶部面包屑、主题切换、用户区域属于公共 Shell。
- 页面路径继续保留在 `admin-system/`，便于本地按业务路径定位 HTML。
- 当前页面契约暂记录页面级 Tab：`工作台`、`客户管理`、`客户子账号管理`。

### 3.2 业务 Tab

- `角色管理`
- `子账号管理`

### 3.3 子账号管理列表

筛选顺序：

1. 登录账号
2. 商户ID
3. 客户名称
4. 状态

表格列顺序：

1. 商户ID
2. 客户名称
3. 登录账号
4. 姓名
5. 绑定角色
6. 管理余额账户
7. 管理广告账户
8. 状态
9. 最近登录
10. 操作

本轮补充要求：

- 页面不展示业务 Tab 上方的页面标题和说明副标题。
- 表格使用固定列宽，表头和单元格必须保持同一垂直列线。
- “重置密码”行内操作使用危险色文本，确认按钮使用危险按钮样式。

### 3.4 创建子账号

当前草案字段：所属客户、登录账号、姓名、初始密码、绑定角色、状态、管理余额的广告账户、管理广告的广告账户。

### 3.5 字典与格式化

| 字段 | 当前记录 | 状态 |
| --- | --- | --- |
| `status=1` | 启用 | 待产品确认 |
| `status=2` | 停用 | 待产品确认 |
| 空值 | `-` | 页面统一规则草案 |
| 最近登录 | `YYYY-MM-DD HH:mm:ss` | 页面统一规则草案 |
| 账户数量 | `N 个` | 页面统一规则草案 |

## 4. 已发现、但暂不提前固化的差异

当前本地页面脚本与契约存在以下差异，计划在阶段 3 处理：

- 本地 Tab ID 使用 `subAccounts`，契约使用 `sub-accounts`。
- 本地子账号 Tab 缺少“客户名称”筛选，且筛选顺序与真实页面不一致。
- 本地表格缺少“姓名”“管理余额账户”“管理广告账户”“最近登录”等列。
- 本地创建弹窗仍使用“商户ID、角色名、备注”等通用字段，未按创建子账号字段契约实现。
- 本地生成内容由通用 `admin-page.js` 静态配置驱动，尚未读取页面契约和 Fixture。

这些差异是“待实现项”，不是对真实系统的否定，也不应被直接写入全局 UI 规范。

## 8. 本轮第二次验收的修订规则

用户进一步指出筛选控件、表格列线、操作按钮和编辑弹窗仍有瑕疵。本轮已补充以下规则：

- 角色管理和子账号管理的筛选区均使用四列等宽布局。
- 列表表格使用 `table-layout: fixed` 与显式 `colgroup` 宽度，操作列独立固定宽度。
- 行操作使用小尺寸 Link 按钮；操作之间保持固定间距，危险操作使用危险色。
- 编辑弹窗使用页面专属标题，不再使用通用“编辑配置”。
- 编辑弹窗沿用创建弹窗的两列表单网格；账户多选控件的复选框和文本保持左对齐。
- 编辑子账号时所属客户、绑定角色、状态、余额账户等字段应回填当前行数据；初始密码为非必填。
- 角色管理列表的“客户名称”和“角色名”按文本字段处理，表头和单元格统一左对齐。
