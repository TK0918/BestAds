## 2. 当前需要拆分的内容

现有 `运营端UI规范.md` 已经覆盖了大量规则，但部分数值来源于客户管理页面，不能自动推广到所有页面。例如：

- 客户管理的默认分页是 `50条/页`，不应直接推广到所有列表页。
- 客户管理表格行高约 `64px`，客户子账号管理真实页面存在约 `40px` 的 VXE 行高，应记录为页面特例或进一步确认。
- 客户管理的列宽、操作列宽度、可排序字段属于页面契约，不应只写成全局规则。
- 测试环境的菜单、用户信息和权限会随账号变化，原型只能固化结构和状态，不能把当前账号数据当成全局事实。

## 3. 当前基线分层原则

### 全局基线

- Vben Admin + Ant Design Vue + VXE Grid 是运营端前端技术基线。
- OPS 2.0 Figma 是 HTML 原型的视觉与组件基线；当前已确认 `Field`、`Tabs`、`Card`、`Menu_一级`、`table-cell/action`、`Dropdown` 等组件参数。
- 浅色/深色模式属于公共 Shell 能力。
- 页面路径保持在 `admin-system/`，便于本地定位和 Git 展示。
- 空值、状态、金额、时间和操作提示应使用集中字典和格式化规则。

### 页面模式

- `Page + 查询区 + 列表区 + 分页` 是主要列表页模式。
- `Vben Form + Vben Modal` 是真实前端表单弹窗模式。
- `VXE Grid` 是真实列表表格模式。
- 页面实际使用的组件必须以真实前端代码为准，不以目录中“存在但未被使用”的组件为准。

### 页面特例

- 表格列、列宽、默认分页、默认排序字段。
- 页面级 Tab 和业务操作。
- 弹窗字段、权限树结构和状态转换。
- 不同业务域的金额精度、币种换算和状态颜色。
- Figma 客户管理页面使用圆角卡片、四列筛选区和 `#202020` 选中菜单；这是视觉基线，不改变客户管理真实字段和业务操作契约。

### 左侧菜单专项基线（2026-08-09）

- `工作台` 是左侧顶部独立入口，指向 `admin-system/main-functions/index.html`。
- `主要功能` 分组包含：客户管理、客户子账号管理、代理管理、介绍人和吐点、返点配置、其他扣费、地区税费、导出中心。
- `系统配置` 是一级分组，不属于 `主要功能`。
- `系统配置` 分组包含：预充配置、系统字典、权限审计日志、客户端菜单、通知配置、消耗下降提醒配置。
- 本地暂以 `admin-system/main-functions/system-config.html` 承载 `系统字典`，后续可在不破坏已有外链的前提下增加 `system-dict.html` 别名页。

### 业务管理模块专项基线（2026-08-09）

- FB业务管理菜单包含：账户管理、开户管理、账户分配、账户充值、账户减款、账户清零、服务费配置。
- TT业务管理菜单包含：账户管理、账户分配、账户充值、账户减款、账户清零、服务费配置。
- GG业务管理菜单包含：账户管理、账户分配、账户充值、账户减款、账户清零、账户服务费。
- 其他媒体业务菜单包含：账户管理、账户分配、账户充值、账户清零、账户服务费；测试环境当前无账户减款入口。
- 账户管理测试环境字段：
  - FB：广告账户ID、广告账户名称、状态、时区、币种、余额、总消耗、消耗上限、创建天数、创建时间、所属BM、媒体代理、所有者ID、被封原因、开户代理、账户类型、代理更新时间、修改人、操作。
  - GG：广告账户ID、广告账户名称、状态、时区、币种、余额、总消耗、消耗上限、创建天数、创建时间、开户代理、账户类型、代理更新时间、修改人、操作。
  - TT：广告账户ID、广告账户名称、状态、时区、币种、余额、创建天数、创建时间、媒体代理、开户代理、账户类型、代理更新时间、修改人、操作。
  - 其他媒体：媒体、广告账户ID、广告账户名称、币种、余额、创建时间、开户代理、账户类型、更新时间、修改人、操作。
- 账户分配页包含 `当前分配 / 分配日志` Tab；当前分配列表字段为客户ID、客户名称、商户ID、广告账户ID、广告账户名称、开户代理、账户类型、绑定时间、操作人，其他媒体业务前置媒体字段。
- 账户充值、账户减款、账户清零均为资金工单列表；其他媒体业务在列表首列和筛选区增加媒体字段。
- 服务费配置列表字段为广告账户ID、广告账户名称、账户服务费、状态、最后修改时间、最后修改人、代理、代理服务费、操作；其他媒体业务前置媒体字段。

### 客户子账号管理专项基线（本轮根据页面截图复核）

- 角色管理、子账号管理的查询区采用四列等宽控件；操作按钮另起一行靠右对齐。
- 列表表格需要显式列宽和固定布局，避免客户名称、登录账号、角色等长文本改变列线。
- 行操作采用小尺寸 Link 按钮，操作之间保持固定间距；重置密码属于危险操作。
- 创建和编辑弹窗使用两列表单网格，字段控件宽度一致；账户多选的复选框和文本必须左对齐。
- 编辑弹窗的标题和回填数据按业务 Tab 区分，不能使用通用“编辑配置”文案。
- 角色管理列表的客户名称、角色名属于文本字段，表头与单元格统一左对齐；商户 ID、数量、状态等字段保留各自的数值/状态对齐方式。

## 4. 基线更新规则

当真实系统或前端代码发生变化时：

1. 先更新事实基线并记录来源和日期。
2. 判断变化是全局规则、页面特例还是实现缺陷。
3. 只有产品确认后，才更新统一产品规范。
4. 受影响的 Showcase、页面契约、HTML 和 PRD 必须回归。
