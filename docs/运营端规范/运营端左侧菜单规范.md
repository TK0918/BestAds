# 运营端左侧菜单规范

> 版本：`v1.0.0`
> 日期：`2026-08-09`
> 范围：运营端 HTML 原型左侧菜单与页面入口。

## 1. 唯一配置源

- 菜单唯一配置源为 `prototype-kit/admin-shell/admin-menu.js`。
- 业务页面不得再手写完整菜单；旧页面由 `admin-shell.js` 运行时接管菜单。
- 新增页面时只需要新增 HTML 文件和 `admin-menu.js` 配置，其他页面刷新后自动生效。

## 2. 路径规则

- 菜单 `path` 使用仓库根目录相对路径，例如 `admin-system/main-functions/customer-management.html`。
- 页面文件继续保留在业务目录，便于本地查找和 Git 静态站点访问。
- `file://`、本地 HTTP、GitHub Pages 均必须可用。
- 已被外链引用的文件不轻易删除；需要改页面身份时优先保留文件并调整内容。

## 4. 系统配置规则

- `系统配置` 是一级分组，不属于 `主要功能`。
- 测试环境 `/system-dict` 对应菜单项为 `系统字典`。
- 本地暂以 `admin-system/main-functions/system-config.html` 承载 `系统字典`，后续可增加别名页，但不得破坏已有 `system-config.html` 外链。
- 测试环境不存在的菜单项不得放入当前菜单；如需保留旧页面，先标记为 planned 或从菜单隐藏。
- `资产分配核对` 当前不在测试环境 Meta资产管理菜单中，原型菜单隐藏该入口；历史文件暂保留，避免破坏旧链接。
- `其他媒体业务` 当前测试环境无 `账户减款` 菜单，本地菜单不得新增该入口。
- TT 业务管理在测试环境已有完整菜单；本地原型必须提供对应 HTML 文件，不得继续使用 planned 占位。
- `监控管理` 是监控类页面的一级分组，不仅包含余额监控；余额监控&自动充值、账户封停、余额日环比均归属该分组。
- `客户端规则` 不再作为独立二级菜单和独立 HTML 文件维护；客户端侧自动充值规则并入 `余额监控&自动充值` 的 `自动充值设置` Tab。
- `账户余额日环比` 属于 `监控管理` 分组，不属于报表分组；页面标题可为 `账户余额日环比异常`。

## 6. 交互规则

- 打开或跳转到任一页面时，仅当前页面所属一级分组默认展开，其他一级分组默认收起。
- 用户点击一级分组后，可以临时展开/收起该分组下的二级页面。
- 用户在当前页面手动展开/收起一级分组，只作为当前页面的临时查看状态；跳转到其他页面后重新按当前页面所属分组展开。
- 当前页面菜单项必须有选中态。
- planned 或缺少路径的菜单项禁用跳转，并显示待建设状态。
- 菜单折叠状态不做跨页面持久化，避免本地原型因为历史展开状态与测试环境差异过大。

## 7. 回归要求

每次调整 `admin-menu.js` 后至少检查：

- 主要功能分组是否与测试环境一致。
- 系统配置分组是否与测试环境一致。
- 当前页面 active 状态是否正确。
- 跨目录页面跳转是否正确。
- `file://` 和 `http://127.0.0.1:4174` 两种访问方式是否可用。
