# BestAds 运营端 UI 规范

> 版本：`v1.0.0`
> 状态：现行规范
> 首次整理：`2026-08-08`
> 适用范围：`admin-system/` 下的运营端 HTML 原型，以及后续运营端页面的 PRD/原型视觉与交互基线。

## 0. 规范定位

本文件是 BestAds 运营端原型的统一 UI 规范。后续新增或修改运营端原型，必须先遵循本文件；如果真实测试环境或前端实现发生变化，应同步更新本文件，再继续扩展其他原型。

规范优先级如下：

1. 当前测试环境与真实前端实现。
2. 本文件记录的已确认 UI 规则。
3. 既有 HTML 原型中的局部样式。
4. 个人偏好、临时截图或未确认的视觉猜测。

当页面需求与规范冲突时，不要在单个页面中偷偷新增一套样式。应在 PRD/原型验收记录中标注差异，并在本文件的“变更记录”中补充规则或待确认项。

### 0.1 真实基线

- 前端技术基线：Vben Admin + Ant Design Vue + VXE Grid。
- 真实客户管理路由：`/customer-list`。
- HTML 原型入口：按业务页面保留在 `admin-system/` 对应目录，文件名与业务路由保持可定位关系。
- 参考实现：`前端-运营端-frontend/03-design-system.md`、`04-components.md`、`05-patterns.md`、`06-page-baseline-customer-management.md`。
- 当前已对齐页面：`admin-system/main-functions/customer-management.html`。
- 当前测试环境参考：[运营端客户管理](https://operation-test-ads.bestads.com/customer-list)。

### 0.2 原型与真实前端的关系

- HTML 原型用于业务评审、交互演示和前端实现参考，不默认代表已经接入真实 API。
- 原型中的字段、枚举、权限、金额和状态必须尽量来自真实测试环境；无法确认时使用 `待确认`，不能把猜测写成已实现事实。
- 原型必须可点击，至少覆盖默认、筛选、重置、排序、分页、弹窗打开/关闭、提交中、成功、失败、空数据和无权限等关键状态。
- 原型页面可以使用静态 mock，但字段名、展示格式、操作边界应与真实前端契约保持一致。

## 1. 视觉基调

- 关键词：信息密度高、结构清晰、操作直接、弱装饰、强调数据可读性。
- 页面主体使用浅灰背景承载白色卡片，卡片之间保持清晰间距。
- 主操作使用蓝色；行内操作使用蓝色文字链接；危险操作使用红色或确认弹窗，不使用大面积高饱和装饰色。
- 不在运营端页面引入渐变、玻璃拟态、夸张阴影或与现有系统无关的圆角风格。
- 统一使用中文界面文案；代码、路由、API 字段和枚举保留原文。

## 2. 设计 Token

### 2.1 亮色模式

HTML 原型默认使用以下 CSS 变量；真实前端应优先消费 Ant Design/Vben token，不应在业务组件中硬编码同义颜色。

```css
:root {
  --admin-primary: #006be6;
  --admin-page-bg: #f1f3f6;
  --admin-border: #e4e4e7;
  --admin-text: rgba(50, 54, 57, .88);
  --admin-secondary: #606266;
  --admin-muted: #8c8c8c;
  --admin-success: #67c23a;
  --admin-danger: #f56c6c;
  --admin-warning: #d7a51a;
}
```

### 2.2 暗色模式

暗色模式必须通过页面级主题状态切换，不能只修改单个卡片。原型需要支持月亮/太阳按钮切换，并通过 `localStorage` 记住用户选择。

```css
body.theme-dark {
  --admin-page-bg: #18191c;
  --admin-border: #34363b;
  --admin-text: rgba(255, 255, 255, .88);
  --admin-secondary: #b7b9bf;
  --admin-muted: #858990;
}
```

暗色模式的内容卡片使用接近 `#1f2024` 的背景，输入控件和树形区域使用接近 `#24262b` 的背景；主色切换为更亮的蓝色（当前原型为 `#1677ff`）。

### 2.3 尺寸、间距与圆角

| 项目 | 规范值 | 使用说明 |
| --- | --- | --- |
| 页面最小宽度 | `1180px` | 运营端表格页面不做窄屏压缩，超出时横向滚动。 |
| 左侧菜单宽度 | `224px` | 固定宽度，菜单文字不随页面变化。 |
| 顶部 Header 高度 | `50px` | Logo、面包屑、通知、主题、用户区垂直居中。 |
| 页面内边距 | `16px` | 主内容区、卡片之间的基础间距。 |
| 卡片间距 | `16px` | 查询卡片与列表卡片之间保持可见空隙。 |
| 控件高度 | `32px` | 输入框、选择器、普通按钮的默认高度。 |
| 弹窗表单控件高度 | `34px` | 仅用于批量操作或编辑弹窗中的表单控件。 |
| 表格表头高度 | `40px` | 表头文字居中；可排序列显示排序图标。 |
| 表格行高 | `64px` | 允许 BD/AM 等长文本展示，但不无限撑高。 |
| 基础圆角 | `4px` | 输入框、按钮、卡片、标签、表格区域。 |
| 重点弹窗圆角 | `4px` 或 `8px` | 以真实页面同类弹窗为准，不在同一页面混用多种风格。 |
| 网格间距 | `8px` / `10px` / `16px` | 依次用于按钮组、弹窗操作区、卡片布局。 |

### 2.4 字体

- 默认字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", Arial, sans-serif`。
- 页面基础字号：`14px`。
- 辅助说明、表头、分页信息：`12px`–`13px`。
- 页面/弹窗标题：`16px`–`18px`，使用 `font-weight: 600`。
- 运营端不使用大字号营销式标题；页面标题应服务于定位和层级。

## 3. 页面壳层

### 3.1 左侧菜单

- Logo 使用真实 Ads 资源，不用 CSS 重新绘制品牌图形。
- Logo 区与 Header 高度一致，品牌文字为 `Ads`，不得替换成业务页面标题。
- 菜单项默认高度约 `42px`，工作台入口可略紧凑。
- 菜单文字默认 `14px`、常规字重；当前选中项使用主色文字、浅蓝背景和较高字重。
- 菜单分组标题使用灰色 `12px`–`13px`，不使用全大写英文样式。
- 菜单分组支持折叠；折叠图标放在分组标题右侧。
- 不通过左侧竖线、渐变或强阴影表达选中状态；以背景色和文字色为主。

### 3.2 顶部 Header

- 左侧：菜单折叠按钮、面包屑。
- 右侧：通知、浅色/深色切换、用户头像/名称。
- 主题按钮必须有 `aria-label` 和 `title`，浅色模式显示“切换深色模式”，暗色模式显示“切换浅色模式”。
- Header 底部使用 `1px` 边框，不使用明显阴影。

### 3.3 页面 Tab

- 页面 Tab 位于 Header 下方，整体高度约 `48px`。
- 当前页 Tab 使用浅蓝背景、主色文字和 `font-weight: 600`。
- 非当前页使用白底/灰字，hover 使用很浅的蓝色背景。
- 关闭图标使用小尺寸灰色图标，不抢占页面标题视觉焦点。
- Tab 超出可视区域时保留滚动或“更多标签”入口。

### 3.4 内容区

- 页面主体背景使用 `--admin-page-bg`。
- 查询区、列表区、详情区等主要模块使用白色卡片承载。
- 卡片边框使用 `--admin-border`，默认无明显阴影。
- 查询卡片与列表卡片必须有 `16px` 间隔，不能贴在一起。
- 表格区域应使用 `min-height: 0`、内部滚动或等效布局，避免内容把页面撑破。

## 4. 查询区规范

### 4.1 结构

标准列表页结构：

```text
页面
├─ 查询卡片
│  ├─ 查询字段网格
│  └─ 右对齐的重置 / 查询按钮
└─ 列表卡片
   ├─ 左侧业务操作
   ├─ 右侧字段定制 / 导出
   └─ 表格与分页
```

- 查询卡片使用 `16px` 内边距，字段之间使用 `14px` 左右间距。
- 字段标签放在控件上方，标签与控件间距约 `6px`。
- 查询按钮为主按钮；重置按钮为普通按钮。
- 查询按钮组右对齐，不与业务操作按钮混排。

### 4.2 文案与控件

- 文本输入框 placeholder 遵循“请输入 + 字段名”，例如 `请输入客户名称`、`请输入登录账号`。
- 选择器 placeholder 遵循“请选择 + 字段名”，例如 `请选择客户状态`、`请选择BD`。
- 批量内容字段必须明确分隔方式，例如：`粘贴商户ID，一行一个，或使用空格/逗号分隔`。
- 后端枚举优先使用 dict；原型也应集中维护枚举，不在多个页面重复创建含义相同的 map。
- 输入框、选择器和日期控件默认高度 `32px`，focus 使用主色边框和轻微外发光。

### 4.3 查询行为

- 查询提交时清空已选行，避免旧选中项误用于批量操作。
- 重置应同时清空表单、排序状态、筛选结果和已选行。
- 查询中显示 loading；成功后更新列表和总数；失败显示错误提示并保留用户输入。
- 无效的商户ID内容不得默默返回全量数据，应提示格式错误或返回空结果。

## 5. 按钮与操作

### 5.1 按钮类型

| 类型 | 视觉 | 使用场景 |
| --- | --- | --- |
| 主按钮 | `#006be6` 背景、白字 | 查询、添加、确定、提交等页面主动作。 |
| 普通按钮 | 白底、边框、正文色 | 重置、取消、字段定制等次要操作。 |
| 禁用按钮 | 浅灰背景、浅灰字 | 没有选中行、无权限、提交中等场景。 |
| 行内链接 | 无背景、主色文字、约 `12px` | 编辑、权限管理、子账号管理等表格操作。 |
| 危险按钮 | 红色或普通按钮配确认弹窗 | 删除、停用、重置密码、清零等不可逆或高风险操作。 |

- 普通按钮最小高度 `32px`，水平 padding 约 `15px`，圆角 `4px`。
- 按钮组使用 `8px` 间距；页面左侧业务动作和右侧工具动作分组。
- 图标放在文案左侧，图标与文案间距约 `8px`；不要只用图标承载无法猜测的业务动作。
- 批量操作在未选择数据时必须禁用；点击时仍需做一次选中状态校验。

### 5.2 操作列

- 操作列固定在表格右侧，默认宽度 `280px`。
- 行内操作允许换行，按钮之间保持约 `7px` 水平间距。
- 操作列背景与表格保持一致，并使用左侧轻微阴影提示固定列。
- 操作顺序优先：编辑 → 修改账号 → 权限管理 → 子账号管理 → 重置密码；具体页面按业务闭环调整，但不能随机排列。

## 6. 表格规范

### 6.1 基础结构

- 使用 VXE Grid；HTML 原型使用 `table` 模拟，但应保持相同的列顺序、对齐方式和固定列行为。
- 选择列固定左侧，宽度 `50px`。
- 操作列固定右侧，宽度 `280px`。
- 表头高度 `40px`，表头背景使用浅灰色；数据行高度约 `64px`。
- 默认开启行 hover；hover 只改变背景，不改变文字层级。
- 横向内容超出时保留横向滚动，不缩小到不可读。

### 6.2 客户管理当前标准列顺序

除选择列和最右侧操作列外，客户管理当前标准顺序为：

```text
客户ID → 客户名称 → 商户ID → 客户级别 → BD → AM → 客户状态 → 币种
→ 当前余额 → 已用额度 → 信用额度 → 预充金额上限 → 剩余预充金额
→ 可用余额 → 真实金额 → 冻结金额 → 注册时间 → 最近登录
```

如启用字段定制，用户可隐藏或调整业务列，但操作列必须始终保持最右侧。

### 6.3 对齐与展示

- ID、名称、级别、BD、AM、状态、币种、时间：默认居中。
- 金额、额度、比例、数量：默认右对齐。
- 长文本使用 `EllipsisTooltip` 或等效的“溢出可查看全文”方案；禁止只截断而无法查看完整内容。
- 空值统一显示 `-`，不要混用空白、`null`、`N/A`、`undefined`。
- 状态优先使用字典 label 和 color，再渲染 Tag；不要在页面散落重复颜色判断。

### 6.4 排序

当前客户管理已确认可排序字段：

- `已用额度`
- `信用额度`
- `可用余额`
- `真实金额`
- `冻结金额`

排序表头显示上下方向图标；默认无激活方向，点击后在升序、降序、恢复默认之间切换。真实前端通过 `SortableHeader` 输出 `ASC` / `DESC`，HTML 原型需提供等效可点击反馈。

### 6.5 数字、金额与币种

- 商户ID是公司给客户的身份ID，当前规则为 `5位纯数字`，现阶段以 `1` 开头，例如 `14656`。
- 客户ID按测试环境真实值展示；不要使用 `C001` 之类的演示前缀替代真实格式。
- 币种只显示币种代码，例如 `USD`、`GBP`、`EUR`，不在金额前拼接 `$`。
- 金额使用英文千分位：`99,999,919.99`。
- 小数位保留后端实际精度，当前样例允许 `0`、`102.05`、`99,857.4`、`99,999,919.99`，不要强制所有值补成两位小数。
- 正金额使用绿色，负金额使用红色，零值使用正文色；颜色不能代替数字本身。
- 真实多币种换算规则属于业务/资金契约，不在 UI 层自行换算；页面只展示接口提供的币种与金额。

### 6.6 时间与分页

- 时间格式优先使用 `YYYY-MM-DD HH:mm:ss`；没有登录时间显示 `-`。
- 客户管理默认每页 `50` 条，可选 `[20, 50, 100, 200, 500]`。
- 分页区显示总条数、当前范围、页码和前后翻页按钮。
- 分页、筛选、排序必须能够互相组合；数据刷新后保持当前页面约定的排序和筛选状态，重置时清空。

## 7. 标签、状态与空值

- 成功/启用：浅绿色背景、绿色文字，例如 `启用`。
- 失败/停用：浅红色背景、红色文字，例如 `停用`。
- 客户级别：浅蓝背景、主色文字；当前测试环境中的 `A`、`B` 等值原样展示。
- 空值统一为 `-`，且 `-` 不使用红色，避免把未知误解为错误。
- 需要说明原因的状态，应通过 Tooltip、辅助文案或详情弹窗补充，不把长解释塞进表格单元格。

## 8. 弹窗、抽屉与通知

### 8.1 弹窗

- 遮罩使用半透明黑色并带轻微 blur；弹窗居中显示。
- 标题区、内容区、底部操作区分层清晰，底部使用上边框。
- 普通编辑弹窗宽度参考 `900px`，最大不超过视口 `90%`。
- 批量修改弹窗参考 `680px`；批量功能开关/权限树参考 `900px`。
- 重置密码等确认弹窗参考 `416px`，使用轻量警示图标、说明文本和取消/确定按钮。
- 点击遮罩是否关闭，按真实业务组件规则决定；高风险确认默认不可点击遮罩关闭。
- 打开弹窗时 reset 表单；编辑场景再回填数据；关闭后不保留上一次脏数据。

### 8.2 表单与提交

- 确定按钮在提交中显示 loading 并禁止重复提交。
- 成功后关闭弹窗、刷新列表并显示成功提示。
- 失败后保留弹窗和用户输入，显示可理解的错误信息。
- 必填项使用红色 `*`；校验文案靠近对应字段。
- 权限树使用树结构，父子勾选行为以真实接口和前端实现为准，不在原型中自创另一套语义。

### 8.3 通知

- 成功、失败、警告、信息使用统一 Toast/Notification 样式。
- 提示文案应包含“做了什么”和“结果是什么”，必要时包含影响条数。
- 不使用浏览器原生 `alert` / `confirm` 作为运营端最终交互；重置密码、批量修改、权限变更使用页面内统一弹窗。

## 9. 主题切换

- 页面右上角必须预留主题切换入口，图标使用月亮/太阳语义。
- 亮色模式按钮文案为“切换深色模式”；暗色模式按钮文案为“切换浅色模式”。
- 主题切换需同步影响：页面背景、侧边栏、Header、Tab、卡片、表单、表格、固定操作列、弹窗、分页和通知。
- 主题状态存储 key 当前约定为 `bestads-theme`，可选值为 `light` / `dark`。

## 10. 权限、路由与数据边界

- 页面显示不等于用户一定有权限；真实前端使用 `v-access`/`accessCodes` 控制菜单和按钮。
- 原型中应展示无权限、禁用和未选中状态，不默认所有按钮永久可用。
- 页面跳转路径要与运营端业务目录和真实路由对应；例如客户子账号管理需要携带 `customerId` 或等效业务标识。
- 商户ID、客户ID、BD、AM、币种、余额和权限数据均属于业务数据；原型 mock 不得混用另一套演示格式。
- 资金页面只展示广告系统记录与 Fund 返回的资金结果，不在 UI 层虚构资金中台逻辑。

## 11. HTML 原型落地规则

### 11.1 文件与目录

- 保留与运营端业务页面相近的目录结构，便于本地按页面查找和 Git 展示。
- 新页面优先放入 `admin-system/` 对应业务目录，文件名使用清晰、稳定、可搜索的英文 kebab-case。
- 公共视觉变量、公共组件和页面验收说明优先放入 `prototype-kit/`；业务页面保留自身入口和 mock 数据。
- 不为了“工程化”强制把所有页面迁移到难以按业务定位的 `src/pages` 结构。

### 11.2 页面实现

- 每个页面都要有清晰的页面壳层、查询区、命令区、内容区、分页和弹窗挂载点。
- 样式优先使用本规范中的 CSS 变量；禁止在同一页面重复定义同义颜色。
- 所有主要按钮和表格操作必须有实际点击反馈；静态展示页面也要实现必要的状态切换。
- mock 数据建议与页面同名保存为 `.mock.json`，页面规则、字段、路由和权限建议保存为 `.spec.yml` 或同级说明文件。
- 页面完成后必须用浏览器实际打开验证，不能只检查 HTML 源码。

### 11.3 数据与状态

每个列表页至少准备以下状态：

- 默认数据
- 查询结果
- 空结果
- loading
- 请求失败
- 无权限
- 禁用按钮
- 弹窗表单校验失败
- 提交中
- 提交成功
- 提交失败
